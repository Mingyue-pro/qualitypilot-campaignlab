# CampaignLab V1.0 产品需求

- 状态：已确认的开发基线，运行时代码正在按本文重构
- 定位：受 MDP 经验启发、使用合成业务和模拟渠道的营销流程测试系统
- 非目标：复刻原公司系统、使用真实客户数据、连接真实短信/外呼平台

## 用户与目标

营销运营人员需要选择目标客群、配置营销策略、提交审批并启动执行；审批人员控制营销计划是否可运行；测试人员需要从 API、数据库事件和监控指标验证业务结果。

## V1.0 主流程

```text
创建客群 → 创建营销计划 → 配置策略 → 提交审批 → 批准
→ 启动执行 → 过滤/互斥/频控/分流 → 模拟渠道触达 → 监控结果
```

## 功能范围

### 客群

- 使用明确标识的合成用户数据。
- 支持按 `city`、`member_level`、`is_new_user` 标签筛选客群。
- 创建客群时保存筛选条件和预估人数。

### 营销计划

- 运营人员创建和编辑草稿计划。
- 计划绑定一个客群、一个渠道、时间窗口、频控规则和对照组比例。
- 计划经过提交、批准后才可启动。
- 支持暂停、恢复和结束；结束后不能恢复。

### 策略执行

用户按以下顺序处理：

1. 标签/客群匹配；
2. 已营销互斥；
3. 时间窗口频控；
4. 通过稳定用户指纹分入对照组或营销组；
5. 仅营销组进入模拟短信或外呼渠道；
6. 记录每个用户的结果和唯一主原因。

### 监控

每次执行保存：目标人数、进入人数、标签过滤人数、互斥人数、频控人数、对照组人数、下游接收人数、触达成功数和失败数。各分类必须能够回溯到用户级执行记录。

## V1.0 验收

- 非运营人员不能创建、编辑、提交或启动计划。
- 非审批人员不能批准或拒绝计划。
- 未批准计划不能启动。
- 暂停和结束状态不产生新的渠道事件。
- 对照组用户不能产生渠道触达事件。
- 被互斥或频控拦截的用户不能进入渠道。
- 同一执行批次重试不能产生重复渠道事件。
- 汇总指标能够由用户级执行记录重新计算。
- 所有固定数据可以重置并重复运行。

## 延期

- 真实 Redis、Kafka、Doris、短信和外呼集成；
- 可视化拖拽流程编排；
- 多层频控和互斥优先级（作为 V1.1 新需求）；
- 查分、SFTP 和外部数据商链路。
